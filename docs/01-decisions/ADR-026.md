# ADR-026 — Porte build de la console : mode compile seul sur le poste Windows, build complet en CI et dans la VM

**Statut :** PROVISOIRE — en attente de relecture du propriétaire
**Date :** 2026-08-26
**Source :** TACHE-00 tâche 5 ; incident de build Next.js sur le poste

## Contexte

Le prerender statique de `next build` échoue systématiquement sur le poste
Windows avec `InvariantError: Expected workStore to be initialized` — bug
amont ouvert (vercel/next.js#87719), reproduit avec Next 15.5 et 16.3, avec
webpack et Turbopack, y compris sur un projet `create-next-app` vierge. Le
même projet, même Node 20.20.2, builde intégralement en vert dans un conteneur
`node:20` Linux (preuve du 26 août 2026). La compilation locale passe
(`✓ Compiled successfully`) ; seule la phase de prerender casse.

## Décision

La porte `build` du Makefile détecte l'environnement : sous Git Bash Windows
(`MSYSTEM` défini), la console est buildée avec
`next build --experimental-build-mode compile` (compilation réelle, sans
prerender), avec un avertissement affiché. Partout ailleurs — CI ubuntu-latest
et machine virtuelle — le `next build` complet s'exécute. La porte lourde de la
VM DOIT builder la console complètement.

## Alternatives rejetées

- Bloquer TACHE-00 jusqu'au correctif amont : bloque tout le projet sur un bug
  tiers sans date.
- Builder la console dans un conteneur Docker à chaque `make check` local :
  ~2 minutes supplémentaires par exécution, pour une garantie déjà fournie par
  la CI à chaque poussée.
- Revenir à Next.js 14 : version dépassée pour un projet soutenu en 2027, et
  le bug touche aussi la série 15.

## Conséquences

- Divergence poste/VM bornée et documentée, en écart assumé avec la règle de
  parité ISC-DEPLOY §6.2 : le poste Windows ne vérifie pas le prerender ; la
  CI le vérifie à chaque poussée (vert le 26 août 2026, run 1 min 40).
- À réévaluer à chaque montée de version de Next.js : dès que le bug amont est
  corrigé, le contournement est retiré et cet ADR passe en OBSOLÈTE.
