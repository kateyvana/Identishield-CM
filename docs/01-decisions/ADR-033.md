# ADR-033 — Outils en ligne de commande : Python bibliothèque standard uniquement, zéro dépendance

**Statut :** PROPOSÉ FERME — en attente de clôture par le propriétaire
**Date :** 2026-09-14
**Source :** T2-11 (constat d'implémentation) ; ISC-SRS v1.3 ENF-05 ; ISC-SAD v1.2 §5 (composants outils)

## Contexte

Le SAD v1.2 §5 nomme **Python (Typer)** comme technologie de deux outils en ligne de commande : `isc-hlr-agent` (T2-11) et `isc-attacker` (T2-16). En implémentant `isc-hlr-agent`, l'outil s'est révélé trivial : une sous-commande, quatre paramètres, un POST JSON au cœur. `argparse` et `urllib` (bibliothèque standard) le couvrent entièrement ; Typer n'y apporte rien.

ENF-05 exige qu'un tiers obtienne l'environnement complet opérationnel en moins de dix minutes. Chaque dépendance tierce en moins sert cet objectif : rien à résoudre, rien à télécharger, rien qui casse à une montée de version. CLAUDE.md §8 va dans le même sens (« la solution la plus courte et la plus lisible ; n'introduis pas d'abstraction sans deux usages réels »).

## Décision

Tous les outils en ligne de commande Python du projet (`isc-hlr-agent`, `isc-attacker`, et tout outil CLI ultérieur) sont écrits en **Python, bibliothèque standard uniquement** : `argparse` pour l'interface, `urllib` pour les appels HTTP, `json` pour le corps. **Zéro dépendance tierce d'exécution.** Une seule convention pour tous les outils.

Conséquence directe : **T2-16 (l'outil attaquant) sera aussi en stdlib**, comme `isc-hlr-agent` livré en T2-11.

## Alternatives rejetées

- **Typer** (nommé par le SAD) : ajoute une dépendance (et sa chaîne : click) pour des CLI que la stdlib couvre déjà. Aucun gain de lisibilité ni de fonctionnalité ici ; un coût net contre ENF-05.
- **Une bibliothèque interne partagée** pour les outils (parsing, client HTTP communs) : YAGNI. Deux outils triviaux ne justifient pas une abstraction (CLAUDE.md §8). À réévaluer si un troisième outil partageait réellement du code.
- **Un client HTTP tiers** (requests, httpx) : `urllib.request` suffit pour un POST JSON ; pas de dépendance à justifier.

## Conséquences

- **Correction de spécification requise (encadrement)** : le SAD v1.2 §5 doit remplacer « Python (Typer) » par « Python, bibliothèque standard uniquement » pour `isc-hlr-agent` **et** `isc-attacker`. L'agent de codage ne modifie jamais docs/02-specifications/ (CLAUDE.md §2) : la correction est portée par une nouvelle version du SAD livrée par l'encadrement (demande consignée dans docs/03-revues/).
- `isc-hlr-agent` (T2-11) est déjà conforme : `argparse` + `urllib`, `dependencies = []`.
- T2-16 héritera de cette convention.
- Aucune régression outillée nécessaire : `dependencies = []` dans chaque `pyproject.toml` est la garantie ; une porte pourrait l'asserter si le besoin s'en faisait sentir.
