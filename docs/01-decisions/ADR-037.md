# ADR-037 — Pile de l'application mobile

**Statut :** PROPOSÉ — versions à fixer à l'échafaudage (carte M-05) ; clôture par le propriétaire
**Date :** 2026-09-25
**Source :** ISC-AMD-02 v1.1 §2.4 ; ISC-SAD v1.3 (index des ADR : PROPOSÉ) ; ISC-MOB-SPEC v1.1 §17 ; ISC-MOB-CDC v1.1 §10.2 ; CLAUDE.md §4 (aucune bibliothèque hors de la stack sans ADR préalable)

## Contexte

La stack déclarée du projet comprend « Kotlin Android » (CLAUDE.md §4) sans nommer de bibliothèque. L'application mobile en demande plusieurs. CLAUDE.md §4 interdit d'utiliser une bibliothèque hors de la stack sans ADR préalable. Cet ADR est créé dès maintenant pour déclarer la pile. Les versions exactes seront consignées à l'échafaudage.

## Décision (proposée)

| Couche | Choix | Pourquoi (ISC-MOB-SPEC §17) |
|---|---|---|
| Langage | Kotlin | Langage officiel d'Android, dans l'écosystème JVM du projet |
| Interface | Jetpack Compose + Material 3 | Écrans déclaratifs, testables |
| Architecture | MVVM, ViewModel + StateFlow, coroutines | Simple, testable |
| Injection | Manuelle (constructeurs) | Pas de cadre d'injection pour une petite application |
| Réseau | OkHttp + Retrofit + kotlinx.serialization | Épinglage via `network_security_config` |
| Cryptographie | Android Keystore (`KeyGenParameterSpec`), AndroidX Biometric | Seul moyen d'avoir une clé matérielle liée à l'authentification (SPIKE-1) |
| Préférences | DataStore (données non sensibles seulement) | Aucun secret au repos (MOB-S-10) |
| Tests | JUnit, Turbine, MockWebServer, tests Compose, tests instrumentés sur téléphone physique | Logique, écrans, cryptographie réelle |
| Build | Gradle Kotlin DSL, dossier `mobile/` à la racine | Cohérent avec `core/`, `pdp/`, `console/`, `simulator/` |
| Faux serveur (livrable L-4) | **Outil à nommer** | Généré depuis `contracts/mobile-api.yaml` |
| Lecture de l'attestation côté serveur | **Bibliothèque à nommer, ou API standard seule** | Analyse de l'extension d'attestation du certificat feuille (MOB-S-04) |

## Règles attachées

1. **Aucune de ces bibliothèques n'est utilisée avant la clôture de cet ADR** par le propriétaire.
2. Les versions exactes (dernières stables à la date de M-05) sont consignées ici à l'échafaudage. Ce document n'en fixe aucune.
3. Les deux lignes « à nommer » sont des trous déclarés. Elles doivent être remplies, ou la ligne retirée, avant la clôture.
4. Aucune cryptographie maison (CLAUDE.md §4) : la signature passe exclusivement par Android Keystore côté téléphone et par `java.security` côté serveur.

## Alternatives rejetées (ISC-MOB-SPEC §17.1)

- **Flutter ou React Native.** Le Keystore, la biométrie liée à la clé et `FLAG_SECURE` exigent de toute façon du code Android natif.
- **Application web.** Elle n'a pas accès à une clé matérielle non exportable liée à l'authentification.

## Conséquences

- La porte automatique de l'application (lint, tests unitaires, assemblage) sera branchée sur `make check` à l'échafaudage (QM-12). Elle doit s'exécuter en ligne de commande dans la VM Ubuntu.
- CLAUDE.md §4 (stack) reste inchangé : cet ADR en est l'extension déclarée pour le dossier `mobile/`.
